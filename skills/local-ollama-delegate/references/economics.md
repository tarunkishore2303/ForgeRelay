# What savings mean

The user's billing mode is a ChatGPT/Codex subscription. Keeping the same subscription means zero reduction in its fixed fee. Useful delegation might preserve included allowance, avoid additional credit purchases, or finish more work before limits. This cannot be inferred from Ollama token counts; record usage through the plan dashboard in matched sessions. OpenAI explicitly separates API prices from subscription usage and says context, reasoning, tools and caching affect allowance: https://learn.chatgpt.com/docs/pricing.

For one eligible task, let D be primary-only usage, O be primary delegation overhead (briefing, review, corrections and fallback decision), p be probability that the worker result replaces primary implementation. If a failure still requires full primary implementation, expected hybrid primary usage is O+(1-p)D. Expected usage saved is pD-O. Delegate only when pD exceeds O. This is a simplified model, not a measured result; corrections included in O can be substantial.

If eligible work consumes fraction f of a project's primary usage and overhead is h=O/D, expected project usage reduction is f(p-h). Example assumptions f=.2,p=.8,h=.3 imply 10% allowance savings; f=.2,p=.4,h=.5 imply a 2% increase. Neither estimate was established by this experiment. Failed full tasks imply positive overhead with no observed implementation replacement, so they provide no basis for claiming savings.

Local electricity estimate = power_watts * local_seconds / 3,600,000 * price_per_kwh. This requires observed/assumed whole-machine power and tariff, not a fabricated GPU-only reading. Hardware amortization, human time and baseline power subtraction are not included. Label estimates. Purchasing new hardware solely for unproven savings is outside this workflow.

`economics.py estimate --scenario FILE` reports conditional usage savings and the unchanged subscription fee. `economics.py compare --measurement FILE` compares entered matched primary-only and hybrid usage, checks a nonzero primary baseline and accepted correctness, and reports separate allowance/cash/time differences. It cannot read this session's usage or validate the supplied measurements. Match model, speed mode, task scope, test acceptance, starting context and usage reset window. If the hybrid build fails acceptance, no successful-build savings are reported.
